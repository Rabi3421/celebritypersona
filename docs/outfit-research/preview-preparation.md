## Coordination document

`catalogWriteState` contains one document, initially `{_id:"catalog", version:0}`. `version` increments inside every dependent catalog transaction before catalog reads. This orders concurrent ID allocation and publication checks; a transaction by itself would permit cross-document write skew. It stores no outfit content, personal data, credentials or per-outfit revisions. Failed transactions roll back the increment.

Ordinary outfit saves now require this document and the required indexes, even with imports disabled. Missing readiness refuses the whole save without writing the outfit or hubs. Provisioning must therefore precede activation of the new production backend within an approved write-pause window. It adds no seventh custom index or content backfill. The operator provisions it; runtime needs `find`/`update`, which may require an approved grant for a narrowly scoped role. Never reset an existing compatible version.
